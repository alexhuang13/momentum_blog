Momentum is usually introduced as a way to speed up gradient descent. But when training data is used only once, there is another question to ask: how does momentum change the batch size we can afford to use?

With the same amount of data, a larger batch gives us fewer parameter updates. This post walks through how that tradeoff works for SGD, Polyak momentum, and Nesterov momentum in a simple regression model. The main result is that Polyak lets us use larger batches before data efficiency suffers, while Nesterov can improve data efficiency itself. To see why, we need to look at both learning speed and noise.

Batch size and the data budget

Suppose we have DDD training examples and use each one once. If each batch contains BBB examples, we get

T=DBT=\frac{D}{B}T=BD​

updates. For example, one million examples give us 10,000 updates at batch size 100, but only 1,000 updates at batch size 1,000. The amount of data is unchanged; the number of opportunities to update the model is not.

Larger batches can make better use of parallel hardware. Whether they also make good use of the data depends on how much the optimizer learns in those remaining steps. Throughout this post, the batch size, learning rate, and momentum stay fixed within a run. We can choose them differently when the data budget changes.

A model with fast and slow directions

We use power-law kernel regression to make this question easier to study. The model predicts f(x;θ)=⟨ϕ(x),θ⟩f(x;\theta)=\langle\phi(x),\theta\ranglef(x;θ)=⟨ϕ(x),θ⟩, and the label is the target prediction plus noise:

y=⟨ϕ(x),θ∗⟩+ϵ,ϵ∼N(0,σ2).y=\langle\phi(x),\theta^*\rangle+\epsilon,\qquad \epsilon\sim\mathcal N(0,\sigma^2).y=⟨ϕ(x),θ∗⟩+ϵ,ϵ∼N(0,σ2).

λj≍j−β,λj∣θj∗∣2≍j−(1+sβ).\lambda_j\asymp j^{-\beta},\qquad \lambda_j|\theta_j^*|^2\asymp j^{-(1+s\beta)}.λj​≍j−β,λj​∣θj∗​∣2≍j−(1+sβ).

Here β>1\beta>1β>1 controls how quickly the feature eigenvalues shrink, while s>0s>0s>0 describes how much of the target lies in the slow directions. Smaller sss means a harder learning problem. The symbol ≍\asymp≍ means equality up to constant factors.

We measure the excess prediction risk, which removes the irreducible label noise from the squared-error loss:

Polyak and Nesterov momentum

Let gk(θ)g_k(\theta)gk​(θ) be the average gradient on the fresh batch at step kkk. Ordinary SGD takes the update

θk+1=θk−ηgk(θk),\theta_{k+1}=\theta_k-\eta g_k(\theta_k),θk+1​=θk​−ηgk​(θk​),

where η\etaη is the learning rate. Momentum adds information from the previous update. It is useful to write that previous displacement as vk=θk−θk−1v_k=\theta_k-\theta_{k-1}vk​=θk​−θk−1​.

Polyak: carry the previous update forward

Polyak momentum, also called the heavy-ball method, updates the displacement and parameters as

vk+1=ρvk−ηgk(θk),θk+1=θk+vk+1.\begin{aligned}v_{k+1}&=\rho v_k-\eta g_k(\theta_k),\\\theta_{k+1}&=\theta_k+v_{k+1}.\end{aligned}vk+1​θk+1​​=ρvk​−ηgk​(θk​),=θk​+vk+1​.​

The factor ρ∈[0,1)\rho\in[0,1)ρ∈[0,1) controls how much of the previous displacement we retain. When consecutive gradients point in similar directions, their contributions accumulate.

Nesterov: evaluate the gradient a little ahead

Nesterov uses the same previous displacement to form a look-ahead point, then evaluates the gradient there:

θkla=θk+ρvk,vk+1=ρvk−ηgk(θkla),θk+1=θk+vk+1.\begin{aligned}\theta_k^{\mathrm{la}}&=\theta_k+\rho v_k,\\v_{k+1}&=\rho v_k-\eta g_k(\theta_k^{\mathrm{la}}),\\\theta_{k+1}&=\theta_k+v_{k+1}.\end{aligned}θkla​vk+1​θk+1​​=θk​+ρvk​,=ρvk​−ηgk​(θkla​),=θk​+vk+1​.​

The change looks small: only the location of the gradient evaluation moves. In a quadratic problem, however, the gradient changes more in high-curvature directions. The look-ahead step therefore changes how different directions are damped. This will matter when we look at noise.

The effective learning rate

To get some intuition for the size of a momentum update, imagine a gradient ggg that stays approximately constant and start from v0=0v_0=0v0​=0. Unrolling the Polyak update gives

vk+1=−η∑i=0kρig=−η1−ρk+11−ρg.v_{k+1}=-\eta\sum_{i=0}^{k}\rho^i g=-\eta\frac{1-\rho^{k+1}}{1-\rho}g.vk+1​=−ηi=0∑k​ρig=−η1−ρ1−ρk+1​g.

Once the initial contribution has faded, the multiplier is approximately η/(1−ρ)\eta/(1-\rho)η/(1−ρ). This motivates the effective learning rate

ηρ:=η1−ρ.\eta_\rho:=\frac{\eta}{1-\rho}.ηρ​:=1−ρη​.

The constant-gradient example is an intuition, not a replacement for the stochastic dynamics. But the same quantity governs the long-run learning of the slow directions for both momentum methods. For example, ρ=0.9\rho=0.9ρ=0.9 gives ηρ=10η\eta_\rho=10\etaηρ​=10η, while ρ=0.99\rho=0.99ρ=0.99 gives 100η100\eta100η.

Choosing a stable learning rate

Increasing ρ\rhoρ makes the effective learning rate larger. Before using that to accelerate learning, we need to check that the error stays bounded. In the large-batch, high-momentum setting, the largest stable learning rate scales as follows:

Learning speed and the noise floor

After the early transient has settled, error has two main contributions. One comes from the signal the model has not learned yet; it decreases with the number of updates. The other comes from stochastic noise and leaves a floor that more updates alone cannot remove.

For SGD, the scaling law is

ESGD(k)≍(kη)−s⏟signal still to learn+σ2ηB⏟noise floor.\mathcal E_{\mathrm{SGD}}(k)\asymp\underbrace{(k\eta)^{-s}}_{\text{signal still to learn}}+\underbrace{\frac{\sigma^2\eta}{B}}_{\text{noise floor}}.ESGD​(k)≍signal still to learn(kη)−s​​+noise floorBσ2η​​​.

A larger η\etaη reduces the first term but increases the second. A larger batch reduces the noise per update, although under our fixed data budget it also reduces the total number of updates.

Polyak keeps the same tradeoff

For Polyak, replace η\etaη with the effective learning rate ηρ\eta_\rhoηρ​:

EPolyak(k)≍(kηρ)−s+σ2ηρB.\mathcal E_{\mathrm{Polyak}}(k)\asymp(k\eta_\rho)^{-s}+\frac{\sigma^2\eta_\rho}{B}.EPolyak​(k)≍(kηρ​)−s+Bσ2ηρ​​.

Momentum speeds up the learning term, but raises the noise floor at the same time. The shape of the signal–noise tradeoff is unchanged. What changes is the range of effective learning rates that remain stable.

Nesterov reduces the noise penalty

Nesterov has the same leading learning term, with a different noise floor:

ENesterov(k)≍(kηρ)−s+σ2Bmin⁡{ηρ,ηρ1/β}.\mathcal E_{\mathrm{Nesterov}}(k)\asymp(k\eta_\rho)^{-s}+\frac{\sigma^2}{B}\min\{\eta_\rho,\eta_\rho^{1/\beta}\}.ENesterov​(k)≍(kηρ​)−s+Bσ2​min{ηρ​,ηρ1/β​}.

When ηρ≲1\eta_\rho\lesssim1ηρ​≲1, this looks like Polyak. When ηρ≫1\eta_\rho\gg1ηρ​≫1, the noise grows as ηρ1/β\eta_\rho^{1/\beta}ηρ1/β​, which is slower than ηρ\eta_\rhoηρ​. In this model, the look-ahead step damps sharper directions more strongly, reducing their noise accumulation while preserving the power-law learning term.

So Nesterov can increase the effective learning rate with a smaller noise penalty. That is the ingredient we need to improve data efficiency.

From training steps to data efficiency

We can now return to the fixed data budget. Substitute T=D/BT=D/BT=D/B into the error formulas and define the effective learning rate per sample:

For example, doubling both the batch size and the effective learning rate keeps aaa unchanged. This quantity makes it easier to compare runs that use the same data in different numbers of steps.

Why Polyak supports larger batches

Once the transient is negligible, SGD and Polyak both give

E(D)≍(Da)−s+σ2a.\mathcal E(D)\asymp(Da)^{-s}+\sigma^2a.E(D)≍(Da)−s+σ2a.

This is SGD’s critical batch scale. Beyond it, even the largest stable learning rate is too small to reach the balance. Polyak has more room because its stability limit gives a≲1a\lesssim1a≲1, so the same optimum remains accessible at larger batches.

A few things to take away

Polyak and Nesterov both accelerate learning through the effective learning rate η/(1−ρ)\eta/(1-\rho)η/(1−ρ). Polyak keeps the same best balance between learning and noise as SGD, but can reach it at larger batches. Nesterov reduces the noise penalty at large effective learning rates, improving the balance itself.

The batch size determines whether we can use those benefits. Small batches give all three methods the same data-scaling exponent. Intermediate batches leave room for momentum to help. Very large batches eventually leave too few updates for either momentum method.

These results are for one-pass kernel regression with fixed hyperparameters during each run. They give a reason to think about the learning rate, batch size, and momentum together. Allowing these settings to change over training is a natural next step.
