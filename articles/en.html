How Does Momentum Help Large-Batch Training?

{{BYLINE}} {{POST_META}}
{{CONTENTS}}

Momentum is usually introduced as a way to speed up gradient descent. But when training data is used only once, there is another question to ask: how does momentum change the batch size we can afford to use?

With the same amount of data, a larger batch gives us fewer parameter updates. This post walks through how that tradeoff works for SGD, Polyak momentum, and Nesterov momentum in a simple regression model. The main result is that Polyak lets us use larger batches before data efficiency suffers, while Nesterov can improve data efficiency itself. To see why, we need to look at both learning speed and noise.

Batch size and the data budget

Suppose we have \(D\) training examples and use each one once. If each batch contains \(B\) examples, we get

\[T=\frac{D}{B}\]

updates. For example, one million examples give us 10,000 updates at batch size 100, but only 1,000 updates at batch size 1,000. The amount of data is unchanged; the number of opportunities to update the model is not.

Larger batches can make better use of parallel hardware. Whether they also make good use of the data depends on how much the optimizer learns in those remaining steps. Throughout this post, the batch size, learning rate, and momentum stay fixed within a run. We can choose them differently when the data budget changes.

A model with fast and slow directions

We use power-law kernel regression to make this question easier to study. The model predicts \(f(x;\theta)=\langle\phi(x),\theta\rangle\), and the label is the target prediction plus noise:

\[y=\langle\phi(x),\theta^*\rangle+\epsilon,\qquad \epsilon\sim\mathcal N(0,\sigma^2).\]

The features are Gaussian, with covariance \(H\). In its eigenbasis, the eigenvalue \(\lambda_j\) tells us the curvature along direction \(j\). Large-eigenvalue directions are easier to learn quickly; small-eigenvalue directions take longer. The feature spectrum and target obey

\[\lambda_j\asymp j^{-\beta},\qquad \lambda_j|\theta_j^*|^2\asymp j^{-(1+s\beta)}.\]

Here \(\beta>1\) controls how quickly the feature eigenvalues shrink, while \(s>0\) describes how much of the target lies in the slow directions. Smaller \(s\) means a harder learning problem. The symbol \(\asymp\) means equality up to constant factors.

We measure the excess prediction risk, which removes the irreducible label noise from the squared-error loss:

\[\mathcal E(\theta)=\frac12\sum_j\lambda_j(\theta_j-\theta_j^*)^2.\]

Below, we call this quantity “error” for short, and write \(\mathcal E(k)\) for its expectation after \(k\) updates. For the data-scaling results, \(\sigma^2\) stays at constant order as the dataset grows.

Polyak and Nesterov momentum

Let \(g_k(\theta)\) be the average gradient on the fresh batch at step \(k\). Ordinary SGD takes the update

\[\theta_{k+1}=\theta_k-\eta g_k(\theta_k),\]

where \(\eta\) is the learning rate. Momentum adds information from the previous update. It is useful to write that previous displacement as \(v_k=\theta_k-\theta_{k-1}\).

Polyak: carry the previous update forward

Polyak momentum, also called the heavy-ball method, updates the displacement and parameters as

\[\begin{aligned}v_{k+1}&=\rho v_k-\eta g_k(\theta_k),\\\theta_{k+1}&=\theta_k+v_{k+1}.\end{aligned}\]

The factor \(\rho\in[0,1)\) controls how much of the previous displacement we retain. When consecutive gradients point in similar directions, their contributions accumulate.

Nesterov: evaluate the gradient a little ahead

Nesterov uses the same previous displacement to form a look-ahead point, then evaluates the gradient there:

\[\begin{aligned}\theta_k^{\mathrm{la}}&=\theta_k+\rho v_k,\\v_{k+1}&=\rho v_k-\eta g_k(\theta_k^{\mathrm{la}}),\\\theta_{k+1}&=\theta_k+v_{k+1}.\end{aligned}\]

The change looks small: only the location of the gradient evaluation moves. In a quadratic problem, however, the gradient changes more in high-curvature directions. The look-ahead step therefore changes how different directions are damped. This will matter when we look at noise.

The effective learning rate

To get some intuition for the size of a momentum update, imagine a gradient \(g\) that stays approximately constant and start from \(v_0=0\). Unrolling the Polyak update gives

\[v_{k+1}=-\eta\sum_{i=0}^{k}\rho^i g=-\eta\frac{1-\rho^{k+1}}{1-\rho}g.\]

Once the initial contribution has faded, the multiplier is approximately \(\eta/(1-\rho)\). This motivates the effective learning rate

\[\eta_\rho:=\frac{\eta}{1-\rho}.\]

The constant-gradient example is an intuition, not a replacement for the stochastic dynamics. But the same quantity governs the long-run learning of the slow directions for both momentum methods. For example, \(\rho=0.9\) gives \(\eta_\rho=10\eta\), while \(\rho=0.99\) gives \(100\eta\).

Choosing a stable learning rate

Increasing \(\rho\) makes the effective learning rate larger. Before using that to accelerate learning, we need to check that the error stays bounded. In the large-batch, high-momentum setting, the largest stable learning rate scales as follows:

MethodLargest stable learning rate
SGD\(\eta_{\mathrm{SGD}}^{\mathrm{crit}}\asymp1\)
Polyak\(\eta_{\mathrm{Polyak}}^{\mathrm{crit}}\asymp\min\{1,B(1-\rho)\}\)
Nesterov\(\eta_{\mathrm{Nesterov}}^{\mathrm{crit}}\asymp\min\{1,B^\beta(1-\rho)\}\)

Read the Polyak row by holding \(\eta\) fixed. As \(\rho\) approaches one, \(1-\rho\) shrinks, so we need a larger batch to compensate. Nesterov gets a stronger compensation, \(B^\beta\), because \(\beta>1\).

Equivalently, Polyak allows \(\eta_\rho\lesssim B\), while Nesterov allows \(\eta_\rho\lesssim B^\beta\). These are scaling relations, with constant factors suppressed; the learning rate \(\eta\) also has a constant-order ceiling. They explain why large batches give momentum more room, but do not yet tell us which stable setting learns best.

Learning speed and the noise floor

After the early transient has settled, error has two main contributions. One comes from the signal the model has not learned yet; it decreases with the number of updates. The other comes from stochastic noise and leaves a floor that more updates alone cannot remove.

For SGD, the scaling law is

\[\mathcal E_{\mathrm{SGD}}(k)\asymp\underbrace{(k\eta)^{-s}}_{\text{signal still to learn}}+\underbrace{\frac{\sigma^2\eta}{B}}_{\text{noise floor}}.\]

A larger \(\eta\) reduces the first term but increases the second. A larger batch reduces the noise per update, although under our fixed data budget it also reduces the total number of updates.

Polyak keeps the same tradeoff

For Polyak, replace \(\eta\) with the effective learning rate \(\eta_\rho\):

\[\mathcal E_{\mathrm{Polyak}}(k)\asymp(k\eta_\rho)^{-s}+\frac{\sigma^2\eta_\rho}{B}.\]

Momentum speeds up the learning term, but raises the noise floor at the same time. The shape of the signal–noise tradeoff is unchanged. What changes is the range of effective learning rates that remain stable.

Nesterov reduces the noise penalty

Nesterov has the same leading learning term, with a different noise floor:

\[\mathcal E_{\mathrm{Nesterov}}(k)\asymp(k\eta_\rho)^{-s}+\frac{\sigma^2}{B}\min\{\eta_\rho,\eta_\rho^{1/\beta}\}.\]

When \(\eta_\rho\lesssim1\), this looks like Polyak. When \(\eta_\rho\gg1\), the noise grows as \(\eta_\rho^{1/\beta}\), which is slower than \(\eta_\rho\). In this model, the look-ahead step damps sharper directions more strongly, reducing their noise accumulation while preserving the power-law learning term.

So Nesterov can increase the effective learning rate with a smaller noise penalty. That is the ingredient we need to improve data efficiency.

From training steps to data efficiency

We can now return to the fixed data budget. Substitute \(T=D/B\) into the error formulas and define the effective learning rate per sample:

\[a:=\frac{\eta_{\mathrm{eff}}}{B},\qquad\eta_{\mathrm{eff}}=\begin{cases}\eta,&\text{SGD},\\\eta_\rho,&\text{momentum}.\end{cases}\]

For example, doubling both the batch size and the effective learning rate keeps \(a\) unchanged. This quantity makes it easier to compare runs that use the same data in different numbers of steps.

Why Polyak supports larger batches

Once the transient is negligible, SGD and Polyak both give

\[\mathcal E(D)\asymp(Da)^{-s}+\sigma^2a.\]

Since the noise level is constant order, the best choice balances the two terms. Ignoring constant factors,

\[\begin{aligned}(Da)^{-s}&\asymp a\\a^{s+1}&\asymp D^{-s}\\a_*&\asymp D^{-s/(s+1)},\qquad\mathcal E_*\asymp D^{-s/(s+1)}.\end{aligned}\]

For SGD, stability requires \(a\lesssim1/B\). We can reach the balanced choice only while \(D^{-s/(s+1)}\lesssim1/B\), or

\[B\lesssim D^{s/(s+1)}.\]

This is SGD’s critical batch scale. Beyond it, even the largest stable learning rate is too small to reach the balance. Polyak has more room because its stability limit gives \(a\lesssim1\), so the same optimum remains accessible at larger batches.

Why the number of steps still matters

There is a second constraint. At high momentum, the early transient needs roughly \((1-\rho)^{-1}\) updates to relax, with logarithmic corrections. A run of length \(T\) therefore needs \(T(1-\rho)\gtrsim1\) before we can use the long-run formulas.

Together with \(\eta\lesssim1\), this gives the scaling bound

\[\eta_\rho\lesssim T,\qquad a\lesssim\frac{T}{B}=\frac{D}{B^2}.\]

Compare this ceiling with \(a_*\asymp D^{-s/(s+1)}\). Ignoring logarithmic factors, Polyak can keep the small-batch exponent until

\[D^{-s/(s+1)}\lesssim\frac{D}{B^2}\quad\Longrightarrow\quad B\lesssim D^{(2s+1)/(2s+2)}.\]

Beyond that scale, there are too few updates. The learning term is limited by \((T\eta_\rho)^{-s}\gtrsim T^{-2s}\). This explains the \(2s(1-b)\) exponent that will appear below when \(B\) grows as \(D^b\). This argument explains the powers; the paper handles the transient and logarithmic factors in full.

Why Nesterov can improve the exponent

For Nesterov with \(\eta_\rho=Ba\gg1\), the same substitution gives

\[\mathcal E_{\mathrm{Nesterov}}(D)\asymp(Da)^{-s}+\sigma^2B^{1/\beta-1}a^{1/\beta}.\]

Now the batch size remains in the noise term even after we switch to a per-sample learning rate. Because \(1/\beta-1<0\), a larger batch lowers that term at fixed \(a\).

Balancing learning and noise gives

\[\begin{aligned}D^{-s}a^{-s}&\asymp B^{1/\beta-1}a^{1/\beta}\\a_*&\asymp D^{-s\beta/(s\beta+1)}B^{(\beta-1)/(s\beta+1)}.\end{aligned}\]

Substituting back, and writing \(B\asymp D^b\), we get

\[\mathcal E_{\mathrm{Nesterov}}(D)\asymp D^{-\frac{s(1+(\beta-1)b)}{s\beta+1}}.\]

This is the increasing middle branch of Nesterov’s data-scaling exponent. It applies while the large-effective-learning-rate balance is feasible. Eventually the step budget becomes the bottleneck again, and the exponent meets the same \(2s(1-b)\) branch as Polyak.

Putting the batch sizes together

Let \(B=D^{b+o(1)}\), where \(b\in[0,1)\). After choosing the best stable hyperparameters, write final error as \(D^{-r(b)+o(1)}\). A larger \(r\) means more improvement from additional data. The small \(o(1)\) terms allow factors that do not change the leading power.

The three transition points are

\[b_1=\frac{s}{s+1},\qquad b_2=\frac{2s+1/\beta}{2s+1+1/\beta},\qquad b_3=\frac{2s+1}{2s+2}.\]

We have already seen where \(b_1\) and \(b_3\) come from: they are the critical batch exponents of SGD and Polyak. The remaining point, \(b_2\), is where Nesterov’s improving branch meets the limit from too few updates.

What the training runs show

The exponents describe the large-data limit. We also ran simulations in the same regression model to see how these predictions look with finite data.

Same data, different batch sizes

Fix \(D=2^{14}\) and tune the learning rate and momentum at each batch size to minimize final error. SGD, Polyak, and Nesterov start at nearly the same error for small batches. As the batch grows, SGD gets worse first, while Polyak holds near its earlier result for longer.

Nesterov’s error goes lower before turning upward. Over that range, changing the batch size and retuning lets it learn more from exactly the same data.

A few things to take away

Polyak and Nesterov both accelerate learning through the effective learning rate \(\eta/(1-\rho)\). Polyak keeps the same best balance between learning and noise as SGD, but can reach it at larger batches. Nesterov reduces the noise penalty at large effective learning rates, improving the balance itself.

The batch size determines whether we can use those benefits. Small batches give all three methods the same data-scaling exponent. Intermediate batches leave room for momentum to help. Very large batches eventually leave too few updates for either momentum method.

These results are for one-pass kernel regression with fixed hyperparameters during each run. They give a reason to think about the learning rate, batch size, and momentum together. Allowing these settings to change over training is a natural next step.
